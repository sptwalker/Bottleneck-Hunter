# 决策链条 L1→L2→L3→L4 复核与优化方案

> 日期：2026-09-22　范围：只读分析（未改任何代码）
> 起因：美股模拟盘现金长期 ~90%，L2 目标现金 <50% 却始终达不到（详见 Task C 根因分析的延伸）
> 本文在 Task C 之上，进一步复核**整条决策链是否合理**：先立"交易师视角下每层应有的职责与层间契约"这把尺子，再逐层拿现有代码对照，最后给出分优先级的优化方案。

---

## 一、交易师视角：四层 + 投委会应有的职责与层间契约

真实投研机构的决策链，本质是一条"**自上而下定方向、逐层收敛到可执行、再自下而上反馈**"的闭环。每层各司其职，且层与层之间有**明确的输入输出契约**。

### L1 — 宏观策略官 / CIO
- **应起的作用**：判断市场处于什么阶段（牛/熊/震荡/转折）、风险偏好该进攻还是防守，给出**大类仓位的方向性锚**（权益/现金/对冲的大致区间）。
- **交给 L2 的契约**：`regime` + `risk_appetite` + `confidence` → 一组**双边的仓位边界**（权益既有上限也有下限，现金既有上限也有下限）。
- **频率**：低频（周级），除非触发重建条件（VIX 破位、联储紧急行动等）才提前重做。

### L2 — 组合经理 / PM
- **应起的作用**：把 L1 的方向翻译成**一张具体的目标组合**——目标权益/现金/对冲比例、行业配置、个股选择（核心仓/战术仓/观察）、单票与行业上限、组合 beta 上限、各票的三场景估值与买卖触发点。
- **双边性是本质**：目标配置既是"不能超过多少"（天花板），**也是"应该达到多少"（地板/设定点）**。PM 的天职是"把钱配出去到目标结构"，不是"只要不超限就行"。
- **交给 L3 的契约**：一张带**目标权重**的持仓蓝图 + 每票的角色（core/tactical/watch）+ 触发条件。
- **向 L1 反馈**：当实际组合与目标严重偏离、或市场变化使目标失效时，请求 L1 复核。

### L3 — 交易策略师 / 择时
- **应起的作用**：在 L2 蓝图约束下，对**每只票**判断未来 5-10 天该 buy/add/sell/reduce/hold，结合催化剂、技术位、论点有效性择时。
- **关键**：L3 是"**把目标权重变成方向性动作**"的一层——低配的核心票要给 buy/add，超配或论点破坏的要给 reduce/sell。它对**买卖两个方向同等负责**。
- **交给 L4 的契约**：每票一个带方向与理由的战术动作。

### L4 — 执行交易员
- **应起的作用**：把 L3 的方向性动作变成**可下单的序列**——定手数、排现金、查合规（不超单票/行业/beta、不违反 regime 边界）、决定先卖后买的顺序。
- **合规是双向的**：既要拦"买太多/买超限"，**也要提示"权益离目标太远、现金趴太多"这类"配置不足"的违规**。真实交易台，"该配没配"和"配超了"都是要被风控点名的偏差。
- **向上反馈**：被拦下的订单、拒绝原因，回流给 L2/L1 学习。

### 投委会 — 风控合规评审
- **应起的作用**：对 L4 产出的执行计划做独立评审（多视角投票），**否决**不合理的单子，是一道**质量闸门**。
- **本质定位**：它是"**否决权**"，不是"**发起权**"——它能拦掉坏单子，但不该也无法凭空产生"你该买"的单子。发起买入是 L1-L2-L3-L4 主链的职责。

### 一句话总结层间关系
> **L1 定方向（双边边界）→ L2 定目标结构（双边设定点）→ L3 把目标结构变成买卖方向 → L4 把方向变成合规订单 → 投委会否决坏单 → 成交/反馈回流。**
> 整条链要成立，必须**买卖对称**：既有"止损/减仓/否决"这类**收缩力**，也有"建仓到目标/补足低配"这类**扩张力**。任何一层只保留收缩力、砍掉扩张力，现金就会单向棘轮式堆积。

## 二、现有系统逐层复核（对照上面的尺子）

以下对照均以 `decision_engine.py` / `constraint_validator.py` / `regime_mapper.py` / 三个 prompt 的当前代码为准。

### 编排总览（`run_daily_decision` :2205 / `run_full_refresh` :2396）
- **日度** `run_daily_decision`：时效门 → 催化剂/论点时效检查 → **硬止损巡检**（绕过 LLM 直接生成清仓计划，:2251）→ L1 日检 → pre_l2 质量门 + L2 偏离检查 → pre_l3 门 → L3 → pre_l4 门 → L4 → 投委会 → 自动执行 → 更新评分。
- **全量** `run_full_refresh`：时效门 → 刷新新闻 → L1/L2/L3/L4 **全新重生成** → 投委会 → 自动执行。
- **复核结论**：编排骨架是合理的、闭环是通的。**但每一道"额外的门"都是单向收缩的**（见下）。

### L1（`run_macro_strategy` :609 / `run_macro_check` :718）—— ✅ 基本符合
- 产出 `regime` / `risk_appetite` / `regime_confidence`，支持双模型交叉验证，周期语义正确（周级生成 + 日检，日检 `needs_major_revision` 才重建）。
- `decision_macro.md` 还要求输出 `recommended_cash_pct`。
- **符合**：L1 确实在给方向。**唯一小缺口**：L1 的方向如何量化成边界，全靠 `regime_mapper` 硬映射（下条），L1 自己给的 `recommended_cash_pct` 并未强绑定到下游。

### L1→L2 映射（`regime_mapper.get_allocation_bounds` :38）—— ⚠️ 双边边界存在，但下游只用了一边
- `REGIME_MAP`（9 组 regime×risk_appetite）给出的 bounds **本身是双边的**：`equity_min` / `equity_max` / `recommended_equity` / `cash_min` / `cash_max` / `max_single_pct` / `beta_limit`，并按 confidence 插值。
- **也就是说，"权益下限 / 现金上限"这两个扩张侧的数字，系统里明明算出来了**。
- **缺口**：`equity_min` / `cash_max` 只被写进 prompt 文本（`format_bounds_for_prompt`，装饰性）和用于 L2 的对称钳制，**从未进入任何会拦订单的强约束**。扩张侧的边界算了但没人执行。

### L2（`run_strategic_plan` :804）—— ⚠️ 意图双边，落地半边
- **意图是双边的**：`decision_strategic.md` 明确要求输出 `target_allocation{equity_pct, cash_pct, hedge_pct}` 和 `risk_limits.min_cash_pct: 15`，个股分 core(8-15%)/tactical(3-8%)/watch，还要三场景估值。这就是一张标准的"双边目标组合"。
- **确定性钳制** `_clamp_target_allocation`（:957 调用）会把 L2 目标 equity/single/beta 钳进 bounds——但**钳制是对称的**（越上限往下压、越下限往上抬），只改**存下来的目标 dict**，**不产生任何下单动作**。
- **20h 复用缓存**（:835-863）：若上游 L1 未变且 L2 年龄 ≤ 20h（`BH_DECISION_REUSE_HOURS` 默认 20），直接**复用旧 L2、跳过重生成**。省算力初衷合理，但副作用是：**只要 L1 一周不变，L2 目标就一周几乎不动**，当现金已严重超配时，这张"正确的目标"每天被复用却从不被当作"要去够到的设定点"。
- **复核结论**：L2 这一层"想得对"（目标是双边的），但它只是"写下一张目标图纸"，后续没有任何机制**逼着实际组合去逼近这张图纸的权益下限**。

### L2 偏离检查（`run_deviation_check` :1039）—— ⚠️ 算了偏离，但不驱动下单
- 每日确定性计算 `_compute_deviation_drift`（:1079，含现金/权益/行业偏离），注入给 LLM 做**叙述与优先级排序**。
- **关键缺口**：drift（包括"现金超配 40 个百分点"这种信号）**只生成一份偏离报告文本，不会转化成"补仓 X 万到核心票"的执行指令**。系统"看见了"偏离，但没"接线"到 L3/L4 的买入通道。**这是现金棘轮的直接放行点之一。**

### L3（`run_tactical_plans` :1130）—— ⚠️ 卖信号丰富，买信号靠"可选/逐票"
- `decision_tactical.md` 设计良好：core→buy/add 优先，catalyst 失败→reduce/sell，论点失效→sell/reduce，exit_plan 用三场景（bear→止损、base/bull→目标位）。
- **不对称**：卖出侧有一堆**确定性触发**（硬止损巡检 :2251、论点破坏、催化剂失败），买入侧则是**逐票、opt-in**——没有"整体权益低于目标 X%，请优先给核心票 buy 直到补足"这样的**组合级买入驱动**。
- **陈旧中止门** `_STALE_UPSTREAM_DAYS`（:1151）：L1/L2 过期时 L3 会中止——**但硬止损等卖出仍能照常触发**。又一处"上游陈旧时，收缩力照跑、扩张力停摆"的不对称。

### L4（`run_execution_plans` :1571）—— ❌ 缺口最集中的一层
- `actionable` 只处理非 hold/wait 的票（:1585）。
- **熔断只拦买**：`check_account_circuit_breaker`（:1606）熔断态只挡 buy/add，卖出照走。
- **已持仓/近期成交跳过**：`existing_tickers`（pending+resting）+ `_is_recent_duplicate`（`EXECUTION_COOLDOWN_DAYS`）会跳过已持有/刚交易的票——**导致"想加仓到目标"的低配核心票被直接跳过**。
- **建仓地板反成拦路**：`target_shares_for_buy`（`position_sizing.py:193`）有 `_MIN_BUILD_WEIGHT_PCT`(≈3%) 下限，`_sized<=0` 直接 `skipped`（:1894-1898）——小额补仓被丢弃。
- **合规校验只看天花板**：`_full_validate` 里的 **`validate_against_regime`（`constraint_validator.py:451`）只检查 `equity_max` 上限 + `max_single_pct`，完全没有 `equity_min`/`cash` 下限校验**。→ **这就是根因的落点**：整条链里唯一"会拦订单"的 regime 校验，只拦"买太多"，从不拦"买太少/现金太多"。
- **提示词本身偏向不动**：`decision_execution.md` 明写"今天不交易是合法且常见的输出""宁可少买，不可超限"。在缺少扩张侧驱动的前提下，这句话进一步把天平压向"不买"。

### 投委会（`run_committee_review`，在 L4 之后 :2354/2438）—— ✅ 定位正确但强化了单向性
- 位置正确：对 L4 产出的 `pending executions` 逐条多视角评审，否决的进"已拦截"区。
- **它是否决权、不是发起权**（本身合理）。但结果是：**又一道只减不增的闸门**——它能砍掉"买"，但当主链根本没产出"买"时，它无事可做，对现金棘轮毫无纠偏能力。

### 质量门（pre_l2/pre_l3/pre_l4，`quality_gate.run_quality_checks`）—— ⚠️ 全是下行闸门
- pre_l4 红灯 → `l4_blocked=True` → **只保留风控性卖出，阻断所有新建买入**（:2341-2352）。
- 又一处"数据/风险异常时，收缩力照跑、扩张力停摆"的不对称设计。

### 复核总结
| 层级 | 该做的（双边） | 现状 | 缺的那一边 |
|---|---|---|---|
| L1 | 定方向 | ✅ | — |
| L1→L2 映射 | 算双边边界 | ⚠️ 算了 `equity_min`/`cash_max` 但只当装饰 | 扩张侧未进强约束 |
| L2 | 双边目标结构 | ⚠️ 目标对、钳制对称 | 目标不驱动"逼近下限" |
| 偏离检查 | 偏离→动作 | ⚠️ 只出报告 | 不接下单通道 |
| L3 | 买卖对称择时 | ⚠️ 卖有确定性触发 | 无组合级买入驱动 |
| L4 校验 | 双边合规 | ❌ `validate_against_regime` 只看天花板 | **无 `equity_min`/现金下限** |
| L4 门禁 | 中性 | ❌ 熔断/去重/冷却/建仓地板全偏向不买 | 扩张侧被层层跳过 |
| 投委会 | 否决权 | ✅（但只减不增） | — |
| 质量门 | 中性 | ⚠️ 红灯只阻买 | — |

**一句话诊断**：整条链的**收缩力（止损、减仓、熔断、否决、陈旧中止、质量门阻买）密密麻麻且大多是确定性的；扩张力（建仓到目标、补足低配）稀稀拉拉且全是 opt-in 的**。所以现金只会单向棘轮式上升，L2 那张"现金<50%"的正确目标永远够不到。**这不是某个 bug，是"目标被当天花板而非设定点"的系统性架构缺陷。**

## 三、优化方案（分优先级，均给落点/验证/风险）

设计原则：**给链条补上缺失的"扩张侧闭环"，让目标权益成为设定点，而不是新增一堆散乱开关。** 每一条都尽量小改、可回滚、可观测。

### P0 — 根因：把"目标配置"从天花板升级为设定点（闭环驱动器）

**P0-1　`validate_against_regime` 增加权益下限/现金上限校验（对称化）**
- 现状：`constraint_validator.py:451` 只校验 `equity_max` + `max_single_pct`。
- 改法：同一函数里补 `equity_min` / `cash_max` 校验；但**方向要对**——权益低于下限时，**不是拦卖，而是产出一个 `underweight_gap` 信号**（"距目标权益还差 N%，可部署 M 元"），供 L4 生成补仓单、供偏离报告告警。校验函数返回结构里加 `underweight` 字段，而不是简单 block。
- 落点：`constraint_validator.py`（一个函数内补分支）。
- 验证：`test_constraint_validator.py` 加一条——给一个权益 30%、目标下限 60% 的组合，断言返回 `underweight_gap≈30%`。
- 风险：低。只加信号，不改现有拦截逻辑。

**P0-2　权益缺口驱动器：把偏离转成买入意图**
- 现状：`run_deviation_check` 算了 drift 但只做叙述（:1079）。
- 改法：在 L3/L4 之间加一个**确定性的"缺口→建仓意图"生成器**：当 `实际权益% < equity_min` 且有现金，按 L2 的 `core_holdings` 目标权重，对**低配的核心票**生成 `add/buy` 意图（金额 = min(缺口, 可用现金, 单票剩余空间)），再交给 L4 正常走 sizing+合规+投委会。
  - 复用已算好的 `_compute_deviation_drift` 结果，不新增 LLM 调用（`# ponytail:` 纯确定性，缺口大小与目标权重都是现成数值）。
- 落点：`decision_engine.py`（L3 后、L4 前新增一个内部步骤，或并入 `run_tactical_plans` 尾部）。
- 验证：构造现金 90% + L2 目标权益 60% 的账户，跑一轮，断言生成了指向低配核心票的买入意图且总额 ≤ 可用现金。
- 风险：中。必须严守——只在 `equity < equity_min` 时触发，单次部署设步长上限（如每轮最多补 1/3 缺口，避免一次性梭哈）。`# ponytail:` 步长是给现实"分批建仓"留的校准旋钮。

**P0-3　让 L4 的建仓侧门禁对"补足低配"网开一面**
- 现状：`existing_tickers` + `_is_recent_duplicate` + 建仓地板会把"加仓到目标"的低配核心票跳过（:1894）。
- 改法：当买入意图来自 P0-2 的缺口驱动器（标记来源）时：
  - 允许对已持仓核心票加仓（不因 `existing_tickers` 跳过）；
  - 冷却期对"补足低配"豁免（或缩短）；
  - 建仓地板 `_MIN_BUILD_WEIGHT_PCT` 对"补至目标"的单子降低门槛。
- 落点：`decision_engine.py:run_execution_plans` 的跳过分支加来源判断；`position_sizing.py` 地板参数化。
- 验证：低配核心票 + 冷却期内，断言缺口驱动的补仓单不再被 skip。
- 风险：中。要防止"每天反复小额补仓刷单"——靠 P0-2 的步长上限 + 收敛判据（到达目标带内即停）兜住。

> P0-1~3 合起来 = 第一股扩张力（**缺口驱动器**）：算出缺口（P0-1）→ 生成补仓意图（P0-2）→ 让执行层放行（P0-3）。它是**修正力**，止于目标结构。但只有它还不够——它只会"把钱配回目标"，不会"看到好球主动出击"。所以再补第二股扩张力：

**P0-4　机会/信念驱动器：第二股扩张力（主动出击，可越线但必申报）**

- **与缺口驱动器的分工**：缺口驱动器是均值回归（回到目标），机会驱动器是**阿尔法**（抓住超额机会，**可超出目标**）。两者动机、边界、越线权限都不同：

  | | 缺口驱动器（P0-1~3） | 机会/信念驱动器（P0-4） |
  |---|---|---|
  | 动机 | 回到目标结构 | 抓住超额机会 |
  | 边界 | **止于**目标权益 | 可**超出**目标（有界 + 上会） |
  | 性质 | 修正 / 均值回归 | 主动 / 阿尔法 |
  | 信念来源 | 偏离度（现金超配） | 场景期望上行 + 催化剂 + L3 conviction |
  | 越线 | 从不 | 分级，且申报上会 |

- **信念分（复用现成数据，零新增 LLM）**：`期望上行 = Σ(概率×目标价)/现价 − 1`（`create_scenario_valuation` 已存 bear/base/bull 的价+概率）+ 催化剂临近度（`catalyst_tracking`）+ L3 逐票 conviction/priority + 观察池 `composite_score`。信念越高 → 允许突破的软约束越多、允许越线缓冲越大（到硬顶为止）。

- **铁律：分级突破——软约束可被信念突破，硬风控红线永不突破。** "突破"= 把"静默丢弃"变成"申报越线 + 上会 + 记账"，绝不是"绕过风控"：

  | 层级 | 约束 | 信念可否突破 |
  |---|---|---|
  | **A · 可突破**（造成现金棘轮的摩擦闸门，本就该给信念让路） | 冷却期 `EXECUTION_COOLDOWN_DAYS`/`_is_recent_duplicate`、`existing_tickers` 跳过、建仓地板 `_MIN_BUILD_WEIGHT_PCT`、"宁可少买"提示词偏压、L2 20h 复用缓存 | ✅ 信念足够即突破 |
  | **B · 半突破**（只能申报+上会，不能自动执行） | `equity_max` 权益天花板（仅限**有界战术缓冲带**，如 +10pct 且设绝对硬顶）、账户熔断 `check_account_circuit_breaker`、pre_l4 质量门红灯 | ⚠️ 越线必走 `run_committee_review` / 人工确认 + 记 oplog |
  | **C · 永不突破**（信念再高也无关） | 可用现金、**单票硬上限** `get_user_single_cap`/`max_single_pct`、组合 beta 上限、数据时效硬停 `_ensure_price_freshness` | ❌ 信念只能更快到达，绝不越过 |

- **防莽撞护栏（缺一不可）**：① 只有顶档信念才有资格触发 B 类越线；② **每轮 + 每票的越线敞口预算封顶**（防中等信念叠成满仓）；③ 同一票反复越线要冷却（不许对同一信念无限追高）；④ 每次越线**必上会 + 必留痕**（复用 `run_committee_review` + `record_operation`）。

- **落点**：信念分计算放 `position_sizing.py` 或新 `conviction.py`（纯确定性）；触发与越线标记并入 P0-2 的驱动器（`decision_engine.py`）；B 类越线在 L4 生成执行计划时打 `mandate_exception=True` 标记，强制进投委会（`run_daily_decision` Step 5 已有 committee 钩子，改为"有 mandate_exception 时必评审、不自动执行"）。
- **验证**：构造一只期望上行 40%+ 催化剂临近的票 + 权益已达 `equity_max` 的账户 → 断言生成带 `mandate_exception` 的买入意图、金额在战术缓冲带内、且被路由到投委会而非自动执行；构造越单票硬上限的场景 → 断言即使顶档信念也被 C 类拦死。
- **风险**：高（这是唯一会"超出目标授权"的力）。安全全靠 B/C 分级 + 越线预算 + 强制上会。**先把 A 类突破做出来验证收益，B 类越线默认关闭（feature flag），确认护栏可靠后再开。**

> **两股扩张力叠加，才真正配平现状那一堆收缩力**：一个负责"钱别趴着"（缺口驱动），一个负责"好球别错过"（机会驱动），而风控硬红线（C 类）两者都不碰。

### P1 — 补强：消除"上游陈旧/异常时只跑收缩力"的不对称

**P1-1　L2 复用缓存增加"偏离逃生阀"**
- 现状：`BH_DECISION_REUSE_HOURS`（默认 20h）内无条件复用 L2（:835）。
- 改法：复用前加一个判据——若**当前实际组合已严重偏离该 L2 目标**（如现金超配 > 15pct），则**不复用、强制重生成 L2**（让 PM 重新面对"钱没配出去"的现实，可能调整选股/触发点）。
- 落点：`decision_engine.py:836` 复用块加 drift 判据。
- 验证：偏离超阈值时断言 `reused` 事件不出现、走重生成。
- 风险：低。只在偏离大时多花一次 L2 算力。

**P1-2　陈旧中止 / 质量门红灯时，扩张侧与收缩侧一致处理**
- 现状：`_STALE_UPSTREAM_DAYS`（L3 :1151）和 pre_l4 红灯（:2341）都只停买、放行卖。
- 改法：明确策略并文档化——数据陈旧/异常时停买是对的（不能盲目下单），但要**在偏离报告里显式记账"因上游陈旧/质量门红灯，本轮未纠正 N% 现金超配"**，让"该买没买"像"被拦的买"一样在 `operation_log` 留痕（现在 :2323 已给"质量门阻断"留痕，缺"缺口未纠正"这条）。
- 落点：`decision_engine.py` 的留痕逻辑扩一条。
- 验证：红灯 + 存在权益缺口时，断言写入一条 `缺口未纠正` 的 operation_log。
- 风险：极低。纯观测性。

### P2 — 打磨：把"扩张侧"暴露到提示词与前端，闭合认知回路

**P2-1　`decision_execution.md` 补上双边表述**
- 现状：只强调"宁可少买不可超限""不交易也合法"。
- 改法：补一句对称的——"**若组合权益显著低于目标下限且有闲置现金，'不部署'同样是一种需要理由的偏差；请优先按目标权重补足核心仓**"。让提示词与新的确定性驱动器口径一致。
- 落点：`chain/prompts/decision_execution.md`。
- 风险：极低。

**P2-2　前端"账户配置饼图"叠加目标对照**（接 Task A/B 已做的双饼图）
- 现状：已有"当前持仓比例"+"账户配置（含现金）"两张饼图（`cead94c`/`090d34e`）。
- 改法：在"账户配置"饼图旁加一条**目标 vs 实际的权益/现金对照条**（数据来自最新 L2 `target_allocation`），让"现金超配"一眼可见。
- 落点：`web/static/js/simtrading.js` + 复用 `.st-pos-charts` 样式。
- 风险：低。纯展示。
