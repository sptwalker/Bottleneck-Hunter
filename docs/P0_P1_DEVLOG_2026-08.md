### P1-④ 投委会法定人数 + L3 上游新鲜度闸 + context 重建

**改动**
- **(A) 法定人数**：`committee.py` `_fallback_consensus` — 有效（非 error/非 abstain）委员 < `QUORUM_MIN=2` → `verdict=needs_review`「评审员多数失败，人工复核」。堵住「3 弃权+1 approve → approve_ratio=1.0 → approved」的旧漏洞。
- **(C) context 每标的重建**：跨 plan `.update()` 复用可变 dict → 改为每 plan 基于市场级快照浅拷贝再补标的背景；`build_ticker_background` 失败时**明确标注背景缺失**而非沿用上一标的估值。
- **(B) L3 上游新鲜度闸**：`run_tactical_plans` 校验 strategic/macro 新鲜度，陈旧则发 blocking `decision_error`「上游未刷新，跳过 L3」而非静默吃旧；空 L2 选股当降级信号如实标注。

**测试**：7 绿。

**验收 finding 根治（#1，加固）**：验收 agent 发现 round-1 投票绕过既有 `_VOTE_ALIASES` 归一化，`approve_with_modifications`（复数）/`approved`（verdict 风格）掉成 abstain → 误压 `valid_n` → 过度触发 quorum 闸。在 `_fallback_consensus` 读票单点复用现成 `_VOTE_ALIASES` 根治（方向安全：只会更保守），加回归测试。

## 三、偏差说明（mandate：确保开发方向没有任何偏离）

以下每项均为「校准计划的错误假设 / 选更诚实的等效实现 / 同类根因收口 / 诚实性根治」，**方向零偏离**，逐条论证：

| # | 计划原文 | 实际实现 | 为何非方向偏离 |
|---|---|---|---|
| 1 | P1-④(B)「校验 created_at **属今日**」 | 周度阈值 `_STALE_UPSTREAM_DAYS=8` | 计划误设 L1/L2 日更；真实为**周度生成**（`job_weekly_strategy`），日度只 check-not-regen。按「今日」会令 L3 每周 6/7 天被误阻断。方向（上游陈旧→阻断/降级）完全一致，仅阈值校准到真实调度节奏 |
| 2 | P1-④（计划未列此项） | `_fallback_consensus` 读票复用 `_VOTE_ALIASES` 归一化 | 验收发现的加固，非偏差；只会更保守（防有效赞成被误当弃权漏计 quorum） |
| 3 | P1-⑤「gap_note **改为肯定句**」 | **删除** 13F 子句 | 在「未采集」清单里放「已提供」的肯定句本身自相矛盾；且 `_holder_qoq` 降级态（<2 季）无 `institutional_qoq`，硬写肯定句会 over-claim。删除后：有 QoQ 时 chip JSON 自证、无则不声明，零矛盾。验收确认「诚实且比计划建议更稳」 |
| 4 | P1-⑤ 改动点仅 `_chip_context` | 顺加 `committee.py:583 latest_only=True` | 验收发现的**同类跨季混读兄弟路径**；`latest_only` 正为此设计；ponytail 根因收口原则（同类 caller 全覆盖）。属核心修复（防跨季混读）自然边界内收口，非扩大范围 |
| 5 | P1-⑥ scheme+白名单校验 | 校验已实现；注释删「egress_relay 管控」 | 诚实性根治：验收证 egress_relay 不覆盖 webhook 出站。改后如实标注残余盲 SSRF 与升级路径 |
