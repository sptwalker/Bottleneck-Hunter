QuantDinger 全面拆解：数据、信息处理、量化、策略与复盘闭环

QuantDinger（OpenByteInc/QuantDinger）是一个自托管的 AI 量化平台，覆盖加密、美股、港股、A 股、外汇和期货。本报告按源码逐模块审计，结论都标注了出处。每一项都对照 BottleneckHunter 现有模块，判断是值得借鉴、本项目已有，还是应当避开。

审计日期 2026-10-09方式：clone 主分支，5 路并行只读审计源码根 backend_api_python/app/

总评

一句话：QuantDinger 的设计思想很成熟：LLM 只负责解释，方向和仓位由确定性代码决定，下单必须经过多层硬门。统计工具也比较专业，有 PBO、Deflated Sharpe、block bootstrap 和成本压力测试。但它的“学习闭环”很浅，不少看起来标准的基础设施其实没有接线。

对本项目最有价值的三件事：

  1. 它的证据锚定和硬门体系：sha256 证据 ID、去掉无引用的论断、按数据质量给置信度封顶、按指标冲突降级为 HOLD。可以直接用来加固 L3、L4 和投委会的推理输出。
  2. 它的过拟合统计工具：PBO（CSCV）、Deflated Sharpe、成本压力测试。本项目 evaluation.py 目前没有这些。
  3. 它的校准反面教材：持有期不固定、HOLD 太容易判对、不扣基准、在样本内调阈值、修正后的置信度回写污染。用这份清单逐项体检本项目的 signal_calibration 和复盘链，性价比最高。

不建议照搬：Kafka/Celery 分布式架构、策略代码生成沙箱、JEV 外部服务、加密交易所多源接入。本项目不让用户写策略，也不做加密，这些属于 YAGNI。

值得借鉴的工程细节

  • 额度锁存：TwelveData 当日额度用完后，禁用到下一个 UTC 日 00:05，避免一整天反复撞限流（asia_stock_kline.py:~162）。
  • 按状态码退避：Finnhub 全局最小间隔 1.05s，429 退避 60s，403 退避 300s。
  • SWR 缓存：值封装为 {value, stored_at, hard_until=TTL×5}，每个 key 单飞锁，4 个后台刷新 worker，计算失败时保留旧值。
  • 负缓存：失败的报价缓存 2s，无效代码缓存 300s，防止被打爆。
  • 来源与时间元数据：研究数据记录每个 provider 的 success / empty / error，并区分 as_of 和 retrieved_at。规则是“抓取时间绝不当作披露日期”。
  • 交易日历守门：latest_completed_session 只在收盘 +15 分钟后才把当天视为已完成交易日，避免用到未收盘的日线（依赖 exchange_calendars）。
  • 丢弃未完成的 K 线：重采样时去掉最后一根未收盘的 bar，从源头防止前视。

基本面时点（PIT）与股票池

  • available_at 推断：财报日在期末后 120 天内的，取财报日 +1；否则取期末 +91 天（保守滞后）；再否则取同步当天。回测时只加载 available_at ≤ end 的数据并前向填充；市值用当日收盘价乘已公开的股本重算。
  • 股票池有效期：成员带 valid_from / valid_to，剔除时关闭区间，按 as_of 解析；成员数不在预期区间（如 CSI300=300、SP500 在 500–510）时拒绝写库；快照生成内容哈希，便于复现。
  • 残留风险（项目自己也承认）：yfinance 返回重述后的财报，存在前视；开始积累数据之前的回测区间仍用当前成分，有幸存者偏差；退市股不会被置为 inactive。

数据层的缺陷（避坑）

  • 死代码 CircuitBreaker、DataCache、东财和 AkShare 限流器全仓没有调用方。熔断器本身也非线程安全，half_open_calls 从不递增。
  • 伪造数据 2Y 收益率直接取 10Y × 0.85，收益率曲线永远不会倒挂；put_call 字段实际是 VIX/VIX3M。
  • 静默默认 恐惧贪婪失败时返回 50，VIX 失败时返回 18，价格失败时返回 {'last':0}，下游无法区分“真中性”和“取数失败”。
  • 只告警 陈旧 K 线只打 warning，不拒绝，照样进入策略；股票侧没有离群和跳变检测。

二 · 信息处理：LLM 被降级为“证据解释器”

主管线是 Fast Analysis，流程为：采集 → 确定性打分 → 多周期共识 → 构建 prompt → LLM → 后处理硬门。system prompt 第一句就是 “You are the evidence-explanation component… You do not decide data quality, position caps or final execution eligibility.”

证据快照与引用锚定

evidence_id = "ev_" + sha256([market, symbol, metric, source, as_of, value])[:20]
每行证据：evidence_id | metric | value | unit | currency | source | as_of
LLM 输出 → Pydantic(extra="forbid") → 剔除未知 evidence ref → 删除无引用论断
  • 时间戳在未来的证据会被剔除。代码注释记录过一个真实 bug：Finnhub 时间戳因容器时区被读成“未来 8 小时”。
  • 新鲜度阈值：行情 2 天，基本面 180 天，宏观 7 天，新闻 14 天。每个市场定义了必需指标集。
  • 所有 DATA 段都标为不可信证据（防 prompt 注入），历史记忆标为 secondary context; untrusted，confidence 明确说明“不是概率”。

确定性打分

overall = Σ score_i·w_i / Σ w_i   （技术 .35 / 基本面 .20 / 情绪 .25 / 宏观 .20，只对存在的分量归一化）
多周期权重  1H .95 · 4H 1.1 · 1D 1.3 · 1W 1.35，再乘 (1 + min(1, |score|/100))
质量乘子    缺宏观 ×0.85 · 缺新闻 ×0.8 · 缺 RSI 或均线 ×0.65
quality_score = 0.50·coverage + 0.35·freshness + 0.15·(1−conflict)
置信度上限  none 35 / low 55 / medium 75 / high 100
  • 防接飞刀：满足 panic_breakdown（强下降趋势 + MACD 看空 + 24h 跌幅 ≤ −3%，等）时，超卖不再加分，各周期展望分被封顶；共识为 BUY 而 LLM 看空时，覆盖门槛反而抬高到 40 或 55。
  • 新闻关联度分级：新闻分为 direct / material / background，只有前两类参与打分。全球头条默认关闭，起因是“无关冲突新闻被当作该资产的利空”。
  • 弱点：新闻源几乎都不带情绪标签，(pos−neg)/total×60 一项常年接近 0，情绪分实际由地缘正则驱动；24h 涨跌按均值回归打分，在趋势行情里会和均线分量互相抵消。

三 · 量化方法：工具专业，用法有偏

回测引擎（strategy_v2/runtime.py）

  • 按频率计算可见截止点：event_time − freq，多周期引用不会泄露，例如 1h 驱动时要等当天最后一根 bar 收盘，日线才可见。
  • 用开盘价盯市决定仓位：明确禁止拿收盘后的权益决定开盘时的仓位，这是很隐蔽的前视。
  • 成交模型：下一根 bar 开盘价 ×(1±滑点)，佣金和滑点默认各 5bps；单笔不超过 bar 成交量 10%，超出部分做部分成交；停牌和涨跌停时拒单；止损遇跳空按开盘价成交，同一根 bar 多触发时优先止损。
  • 未建模：资金费、借券成本、无风险利率、冲击成本与成交量的关系；限价单触价即成交，偏乐观。

因子研究

  • 信号取 t 收盘，在 t+1 开盘入场、t+1+h 开盘出场；按持有期非重叠采样（index[::h]），避免重叠收益让 IC 自相关。
  • Rank IC，ICIR = mean/std × √(年化/h)；分组数自适应；换手率 = 0.5·Σ|Δw|，往返成本扣两次；单调性取组号与组收益的 Spearman；前后半段稳定性对比。
  • 缺陷：持有期内退市的股票被 dropna 剔除，收益偏高；中性化只做行业去均值，不做市值中性化。

策略进化：统计工具箱

PBO (CSCV)  枚举 C(S,S/2)（超过 2000 种时用种子 1776 抽样）：取 IS 最优，看它在 OOS 的排名 ω
            λ = ln(ω/(1−ω))，PBO = P(λ ≤ 0)
DSR         σ̂_SR = √(1 − γ₃·SR + (γ₄−1)/4·SR²) / √(T−1)
            SR₀ = σ̂_SR·[(1−γ)Φ⁻¹(1−1/N) + γΦ⁻¹(1−1/(N·e))]
            DSR = Φ((SR−SR₀)·√(T−1) / √(…))
Bootstrap   循环块，块长 = min(用户值, n^(1/3))；报告 1–99 分位数和亏损概率
成本压力    佣金和滑点同时 ×1 / 1.5 / 2 / 3，在盲测段上重跑
综合评级    mean(1−PBO, DSR, 1−亏损概率, sigmoid(最高成本档收益/10)) → A≥80 B≥65 C≥50 D

用法上的偏差（照搬时要修正）：

  • 伪 WFO 每个窗口不重新优化参数，选优直接看验证折，所以验证折实际属于样本内，只有末尾 15% 的盲测段是真正的样本外。
  • 单次回测切片 训练期的持仓会带进验证期，embargo 只排除统计，不隔离状态。
  • DSR 偏乐观 SR₀ 用单次估计的标准误代替跨试验方差 √V[SR_n]；N 只计已完成的试验，被剪枝、重复的不算。
  • PBO 统计力弱 S 只有 4–10 折，4 折时只有 6 种组合（原论文建议 S=16）；被剪枝的试验不进入矩阵。
  • TPE 是自写简化版：被剪枝的点不进入历史，坏样本集合因此有偏；网格搜索会完整遍历笛卡尔积，高维时会卡死。

实盘与回测偏差（dry-run deviation）

以每笔实盘成交前最后一根收盘价为参考，slippage_bps = (fill−ref)/ref × 方向 × 10⁴，汇总均值、P90、最大值，按周期分档判定 good / warn / bad，样本少于 5 笔时判 unknown。局限：只比成交价，不检查信号是否一致，漏单、多单都发现不了；结果不会回灌到回测的滑点假设。

四 · 策略与执行：意图与执行分离，fail 方向有意识地选择

  • 声明式意图：策略只输出 order_target_percent(sym, pct, reason=…)，由执行层算差额。反手采用“先平后开”，实盘这一轮只发平仓腿，开仓腿等下一轮仓位同步后再发。
  • manifest 契约：universe、频率、方向、杠杆上限、warmup、code_hash 在编译期固化，越权调用在编译阶段就被拒绝。
  • 两级幂等：意图表 ON CONFLICT(run_id, idempotency_key) DO NOTHING，执行表 UNIQUE(idempotency_key)，交易所侧用 client_order_id 回查，处理“超时但其实已成交”。
  • Fencing token：lease 换主时 token 递增，worker 认领订单时原子校验，旧进程的在途单作废。
  • 仓位归属：账户持仓 = 策略持仓 + 受保护持仓 + 未知，只有账户持仓少于策略分配时才阻断开仓，平仓永远不阻断。
  • AI 否决是不对称的：JEV 和 LLM 过滤只拦开仓和加仓；平仓、止损、紧急减仓都绕过 AI。同一信号指纹被拒后在本周期内闩锁，不再反复询问。
  • fail 方向：AI 过滤 fail-open（AI 故障不影响交易）；预算、缺价、数据覆盖不全 fail-closed。每次决策都写入 qd_ai_decisions。
  • 错误分级停机：致命错误（鉴权、IP、签名）立即停机；可恢复错误（漂移、最小名义金额）只拒这一单；其余错误连续 5 次后停机。
  • 整机权益熔断：按 total_value/starting_cash−1 设止盈、止损、回撤，与单笔止损互相独立。
  • 未接线 账户级风险快照（总杠杆、保证金、手续费预算 5%、资金费预算 2%、单标的敞口）模型完整，但只在 tests 里被调用。
  • 模拟盘、实盘、回测共用同一份策略程序和守卫链，靠 execution_mode 切换账本。但虚拟账本没有成交量上限和资金费，比回测更乐观。

五 · 复盘与学习闭环：只有一条线真正接通

analyze() → qd_analysis_memory（决策 + 共识分 + 指标快照）
   ↓ 每日：validate_unvalidated_older_than(7 天, 200 条)  ← 用“验证时刻的现价”算收益
   ↓ AICalibrationService：|thr| ∈ [10…30] 网格，在 30 天样本上最大化准确率 → qd_ai_calibration
   ↓ _score_to_decision 读取 ±thr（进程缓存 300s）   ← 唯一的自动自适应参数
相似记忆：同标的最近 15 条已验证记录，按 RSI/MACD/均线/波动 打相似分，取 top3 注入 prompt
环节状态问题
结果标签已接通持有期不固定（7 天到积压后几十天）；用现价而非 T+7 历史 K 线；不扣基准，学到的是 beta
正确性判定已接通BUY/SELL 需 ±2%，HOLD 只要 |r|≤5%，HOLD 天然容易判对，准确率最大化会把阈值推高
阈值校准闭环生效样本内网格搜索，无 holdout，样本高度自相关；默认只校准 Crypto；最新一行直接生效，无平滑，可能逐日跳变
置信度校准默认关闭按桶线性缩放（非 isotonic）；修正后的值回写同一列，下一轮统计被污染
相似记忆已接通判对的记录 +0.1 加分，样本偏向成功案例；docstring 写了时间衰减但没有实现
策略复盘 / 偏差 / 进化只出报表LLM 生成的诊断不进入任何后续 prompt；bestParams 不会写回
教训提取不存在全仓 grep lesson 零命中
验证队列有隐患无 ORDER BY、不过滤失败行；取不到价格的行不写 validated_at，每天被重复选中，积累超过 200 条后会挤满 LIMIT，闭环静默停摆

值得借鉴的只有 Copilot 记忆的两个做法。一是人在环确认：识别出候选偏好后，用户确认才写库。二是服务器持有上下文字段：剥离客户端伪造的记忆，摘要中的价格数字替换为 [number]，防止过时报价被当成事实。

七 · 借鉴清单（按优先级）

排序依据是“对决策质量的提升 ÷ 实现成本”。每条都写明落点和最小做法，并且已修正 QuantDinger 自身的偏差。

P0-1

按 QuantDinger 的校准反面教材体检本项目复盘链

逐项核对 signal_calibration、model_calibrator、trade_reviewer：

  1. 标签是否按固定 horizon 取历史收盘价；
  2. 是否扣基准；
  3. HOLD / 观望是否与方向判断对称；
  4. 阈值和权重的拟合是否有留出集；
  5. 校准后的值是否回写原始列；
  6. 验证队列遇到取价失败是否写入终态。

成本：只读审计约 1 天。这是最可能发现“静默停摆”或“自我污染”的地方。

P0-2

给 evaluation.py 加入 PBO 和 Deflated Sharpe

两个纯函数，各约 40 行，用 numpy 和 statistics.NormalDist，不引入新依赖。修正对方的两个偏差：

  • SR₀ 用所有候选配置 Sharpe 的跨试验方差；
  • N 计入所有尝试过的配置。

接入 tuning_engine 和 incremental_ablation 的选优输出。PBO>0.5 或 DSR<0.9 时标记“疑似过拟合”，不自动采纳。

配套：成本压力 ×1/1.5/2/3 重跑 event_backtest，只是一个参数循环。

P0-3

L3、L4 和投委会的输出做证据引用的机器校验

喂给 LLM 的数据行加上短 ID（sha256(ticker|metric|as_of|value)[:12]）。LLM 输出时，用 Pydantic 校验引用 ID 都在本次快照内；没有有效引用的理由降级为“无据”，不计入投委会的赞成票。

落点：decision_engine 的结果解析处，复用现有 Pydantic 模型。这是对方防幻觉体系中最可移植的一环。

P1-1

新闻和催化剂按关联度分级

催化剂入库时标注 direct（点名公司）、material（产业链上下游，有传导机制）、background（宏观或板块噪声）。只有前两类影响个股打分和 L3 战术。本项目做产业链，material 一级正好可以用链上的上下游关系来判定，比对方的正则更准。

P1-2

L3 加入“防接飞刀”硬规则

满足 强下降趋势 ∧ MACD 看空 ∧ 当日跌幅 ≤ −3% 或 跌幅 ≤ −8% ∧ 量比 ≥ 1.3 时，禁止新开或加仓，除非投委会给出明确的“错杀”证据。规则位于 LLM 之后，和观察池硬过滤同层。

P1-3

模拟成交偏差回灌滑点

按 A 股和美股分别统计 (模拟成交价 − 决策时参考价)/参考价 的均值和 P90，与 slippage.py 的假设对照。偏差持续超出时，更新滑点参数并在操作日志留痕。这一步补上了对方“只出报表不回流”的缺口。

P1-4

观察池成员加有效期

入池、出池写入 valid_from / valid_to（或复用操作日志重建），回测和复盘时按 as_of 还原当时的观察池，避免“事后才入池的牛股”抬高历史表现。

P2

零散工程项

  • Gangtise 和 tushare 额度耗尽时锁存到次日（北京时间），不再逐次撞墙；
  • 数据源失败时负缓存几秒；
  • 投委会否决只作用于加风险的动作；
  • 执行单生成按 (market, date, ticker, side) 做唯一键幂等，防止补跑和定时同时触发；
  • 研究数据区分 as_of 和 retrieved_at。

逐项核对现状后再决定，很可能已有部分覆盖。

八 · 反面教材：别学的

  • “看起来标准”的基础设施没接线：熔断器、缓存、限流器、账户级风控都只存在于代码或测试里。本项目“验收必用真实数据证明”的原则正是针对这类问题。
  • 默认值伪装成数据：2Y = 10Y × 0.85、VIX 失败时返回 18、价格失败时返回 0。
  • 名不副实：所谓 walk-forward 不重新优化；文档写了“时间衰减”但没有实现；字段叫 put_call 其实不是认沽认购比。
  • 闭环的准确率指标可以被刷：HOLD 判定宽，阈值就被推高；样本内选阈值，再在同一批样本上报告准确率。
  • 记忆检索给判对的记录加分：喂给 LLM 的先例偏向成功案例，会诱导模型过度自信。
  • 提供方自动切换：同一类分析在不同时间由不同模型生成，影响记忆和校准的可比性。本项目已经记录 provider，校准时应按模型分层统计。
