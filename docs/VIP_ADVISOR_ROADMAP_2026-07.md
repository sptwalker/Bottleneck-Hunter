# VIP 私人账户顾问系统 —— 修订版路线图（2026-07-26）

> 状态：**已批准，Phase A 开工中**。本文件是审计后重制的生产级路线,取代此前 `VIP_ADVISOR_PLAN.md` 的地基阶段划分(P0-P6 已完成部分见该文档,本路线聚焦"接真账户 + 闭环"的下一程)。
> 配套:阶段进度记忆 `project_vip_daily_projection.md`(P1/P2/P3 每日推算+校准已完成)。

## 0. 系统定性(本轮确立)

**本系统为管理员个人专用,单用户,不对外开放。** 多用户隔离机制(Key/market/account_ref 隔离)作为既有地基**保留不动**(拆除风险大于收益),但**新功能一律按单用户设计**:不再为多租户付出额外抽象成本,`user_id` 默认取当前管理员,不做跨用户并发/配额/邀请码扩展。

**产品定位:周期性投资参谋(Decision-Support),不是实时投顾(Real-time Advisor)。** 此定性由数据入口的物理现实决定——VIP 数据来自券商 PDF 结算单的**周期性人工导入**(用户确认:每周或更勤),非券商 API 实时连接。因此:
- 所有对账户的分析、建议、复盘,一律**显式标注"数据截至 X 日"**,不伪装实时。
- 决策产物**止于建议层**(减/持/加 + 理由 + 风险 + 衍生品敞口提示),**不生成精确执行单**(真实成交在券商端手动进行)。
- 这是诚实的边界,不是缺陷。想升级为实时投顾需接券商 API,属另一量级工程,当前不做。

## 1. 审计发现的结构性断层(本路线要解决的根因)

三个并行审计(VIP 数据层 / 决策引擎 / 复盘对话链)对着真实代码得出:

| 断层 | 现状 | 影响的目标 |
|---|---|---|
| **决策引擎只跑模拟盘** | L1-L4 + 4 人投委会全部 `get_sim_account()` 读空 ref 的模拟盘;VIP 真账户唯一出口是单角色 `vip_advisor` 单发报告,进不了四层决策 | G2 完全、G3 个性化 |
| **无统一账户视图** | 数据碎在 7+ 个调用里;chat 的 `_build_facts` 只有持仓+衍生品条款,**无流水/成本/盈亏/曲线/校准** | G1、G2、G4、G5 都受阻 |
| **VIP 侧是开环** | 复盘/经验卡/偏好全部只读模拟盘的 `sim_trades`;`experience_cards` 无 `account_ref` 列;VIP 导入从不触发复盘 | G5 完全 |

**关键的好消息(已验证):成本/盈亏数据在结算单里真实存在。** Citi 月结单 EQUITIES 块 `i-9 单价 / i-8 总成本 / i-5 未实现盈亏` 偏移经 8 只真实持仓验证完全自洽(`qty×单价≈总成本`、`市值−成本≈未实现`),解析器此前只是没抽。Nomura `avg` 列同理。→ **G1 的成本/已实现盈亏可直接解析,无需脆弱的 FIFO 重构。**

## 2. 用户五大目标 · 达成度评估(修订后)

| 目标 | 现状 | 做完预期 | 天花板 |
|---|---|---|---|
| G1 单账户完整视图+自动估值 | 🟡 半成品 | ~80% | 衍生品估值口径(见下)|
| G2 多身份 LLM×宏观×个股→持仓建议 | 🔴 机器齐全未接真账户 | ~70% | 数据周期性(参谋定位) |
| G3 观察池荐新标的 | 🟢 基本可用 | ~80% | 需按账户可交易市场过滤 |
| G4 实时交互问答 | 🟢 基本达成(`vip/chat.py`) | ~85% | 单发式,对话中不实时再查行情 |
| G5 循环复盘+经验卡闭环 | 🔴 VIP 侧开环 | ~70% | 复盘质量依赖导入频率 |

## 3. 已由用户拍板的关键决策(约束后续所有实现)

1. **导入频率:每周或更勤** → 定位=周期性参谋,陈旧度可控。
2. **衍生品估值:分开两个数** → 真值层"账户真实价值"= 结算单事实(股票+现金),**不含衍生品模型估值**;衍生品**单列** `derivative_exposure`(敞口+模型估值+敲出/累计状态)。与现有 `projection.py`"绝不触碰真值层"架构一致。
3. **决策产物:止于建议层** → 真账户不下 L4 执行单,规避执行责任与约束校验错配。
4. **成本/盈亏:结算单直接解析** → 前提是结算单确有(Citi 已验证成立)。无则诚实留空,不猜。

## 4. 修订版四阶段路线(按依赖排序)

### Phase A · 账户完整档案层(G1 收口)—— 地基,开工中
把碎片数据聚成 LLM 能一次消费的单一事实源。
- **A1 成本/盈亏解析**:Citi/Nomura 解析器补抽 `avg_cost`/`cost_basis`/`unrealized_pnl`(偏移已验证);负值用括号解析(复用 `_currency_amount` 的 neg 逻辑,修 META 类亏损项 None 问题)。落进现有 `positions` 表既有空列。
- **A2 档案装配器** `build_account_dossier(account_ref)`:合并 持仓(市值+成本+盈亏)+ 全流水 + 价值曲线 + 近期校准/日志 + **衍生品单列段** `derivative_exposure`(敞口+模型估值,**不并入 total_equity**)。
- **A3 端点** `GET /api/vip/account/dossier`:成为 chat/report/决策的**唯一账户事实源**。
- **验收**:真实 Citi 单跑通,dossier 里成本/盈亏与结算单分毫不差;衍生品在独立段不污染真实权益。

### Phase B · VIP 接入分层决策(G2 收口,止于建议层)—— 最高价值
- **B1** L1-L3 + 投委会加 `account_ref` 形参,默认 `''` 保持模拟盘零回归;**不接 L4 执行**。
- **B2 正面处理两个硬缺陷**(不绕):
  - **跨市场丢仓**:VIP 持仓标的自动纳入价源/催化剂/thesis 覆盖(复用 `collect_priceable_symbols`);无价源标的(港股数字码/欧洲 ISIN)**显式标注"未覆盖"**,绝不静默丢半个组合。
  - **衍生品风险盲区**:`derivative_exposure` 作为**独立风险输入**喂投委会,让"风险建议"看得见杠杆/累计/敲出。
- **验收**:对真实持仓跑一轮 L1-L3+投委会,输出"减/持/加+理由+风险+衍生品敞口",且未覆盖标的被显式列出。

### Phase C · 个性化荐新(G3 收口)—— 依赖 B
- 荐股结合 dossier 做增配/规避/再平衡;**先按账户实际可交易市场过滤**再荐。

### Phase D · VIP 复盘闭环 + 账户级经验卡(G5 收口)
- **D1** `experience_cards` 加 `account_ref` 列(幂等迁移)。
- **D2** 结算单导入触发对已平仓/大变动仓位的归因复盘(复用 `trade_reviewer` 思路,数据源换成 VIP 流水)。
- **D3** VIP 再评估 job:定期用最新行情拷问"这仓还成立吗",沉淀账户经验卡回喂 Phase B。

### 横切(贯穿全程,非独立阶段)
- 每条建议**审计留痕**(已有 `advice_audit_trail` 复用)+ 全程"决策支持,非投资建议"定性(已有 `compliance`)。
- **PDF 解析失败显式告警,不静默**(错误持仓=错误建议,生产红线)。
- 数字防幻觉(已有 `number_guard`)贯穿 dossier/report/chat。

---

## 5. 依赖链与优先级

```
Phase A(档案层, 地基) ──┬──→ Phase B(接决策引擎, 最高价值) ──→ Phase C(个性化荐新)
                        └──→ Phase D(复盘闭环)
```
A 是所有人的地基,回报最快,先开工。B 价值最高。C 依赖 B。D 依赖 A(成本/流水)。

G4(实时问答)已基本达成,列为后续增强(对话内接 dossier + 允许实时再查行情),不单独占阶段。

---

## 6. 最终定性

按上述四阶段 + 用户拍板的四个务实决策落地后,系统能扎实达到**"生产级私人投资参谋"**:LLM 掌握单账户完整视图、多层 AI 对真实持仓出分层建议、结合观察池个性化荐新、实时问答、循环复盘沉淀账户经验。**"完全实时投顾"不在本轮范围**——其天花板是数据入口(PDF 周期导入)而非架构,升级需接券商 API,是诚实且合理的边界。
